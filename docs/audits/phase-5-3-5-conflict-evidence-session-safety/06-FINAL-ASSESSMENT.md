## Remaining Limitations

1. **Session replacement detection relies on `sessionStorage.getItem("aw_admin_token")`.**
   If the authentication mechanism changes (e.g., httpOnly cookies), the staleness
   closures will need updating. This is documented and acceptable for the current
   architecture.

2. **Conflict evidence stored in sessionStorage is ephemeral.** Closing the browser
   tab loses all conflict evidence. This is by design (CE-08) — the server is the
   authoritative ledger, and the idempotency key enables manual reconciliation.

3. **Stale-context storage failures are not surfaced to the UI.** When `isFinStale()`
   is true and `saveConflictEvidence` fails, the error cannot be shown because the
   UI belongs to a different tenant/session. This is documented as a known limitation
   with no safe mitigation short of a global notification system.

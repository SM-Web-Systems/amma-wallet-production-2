## Review Priority Order

### Priority 1: Financial Safety (P52-01)

**Files:** `AdminTenantDetail.tsx`, `credit-op-storage.ts`, `admin.ts` (lines 620-734)
**Question:** Does the state machine prevent double-credits and credit abandonment?

Key properties to verify:
1. Inputs are locked when any CreditOperation exists
2. UNKNOWN state cannot be silently discarded
3. Reconciliation endpoint is read-only (no writes)
4. COMMITTED requires explicit acknowledgment before reset

### Priority 2: Database Isolation (P52-02)

**Files:** `db-harness.ts`, `db-safety.test.ts`, `provision-test-db.ts`
**Question:** Can integration tests ever connect to or modify a production database?

Key properties to verify:
1. `postgres` superuser is rejected
2. Non-localhost hosts are rejected
3. Port 5432 is rejected
4. Production database names are rejected (case-insensitive)
5. Provisioning nonce cannot be self-generated by tests

### Priority 3: 23505 Recovery (P52-03)

**Files:** `api-credit-concurrency.test.ts` (P52-03 describe block)
**Question:** Is the unique-violation recovery path exercised deterministically?

Key properties to verify:
1. Pre-insert guarantees the 23505 path (not timing-dependent)
2. Drizzle error unwrapping is tested
3. Fingerprint mismatch returns 409, not silent acceptance

### Priority 4: Admin Scoping (P52-04)

**Files:** `credit-op-storage.ts`, `credit-op-storage.test.ts`
**Question:** Can admin A inherit admin B's pending operation?

### Priority 5: Documentation Accuracy (P52-05/P52-06)

**Question:** Are lock descriptions and rollback guidance accurate?

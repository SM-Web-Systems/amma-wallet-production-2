## AW-ADMIN-008 — Total balance colour warning

### Current Behaviour
`totalBalance` (sum of all tenant `prepaidXlmBalance` values) is displayed in a stats card
at `AdminConsole.tsx:125` with the class `text-violet-700` regardless of whether the value
is negative or positive.

Individual tenant rows already use conditional colouring (red / amber / neutral at lines
207–213), but the aggregate summary card was omitted.

### Desired Behaviour
- Negative `totalBalance` → `text-red-600`
- Zero or positive → `text-violet-700` (unchanged)
- No amber threshold for now.

### Implementation (applied 2026-07-26)

**AdminConsole.tsx:125** — before:
```tsx
<p className="text-3xl font-bold text-violet-700 mt-1">
```

After:
```tsx
<p className={`text-3xl font-bold ${totalBalance < 0 ? 'text-red-600' : 'text-violet-700'} mt-1`}>
```

### Constraints
- Frontend only — no backend change, no new dependencies.

### Test Strategy
| ID | Steps | Pass criterion |
|----|-------|----------------|
| AW8-1 | Tenant prepaid balances sum to > 0 | Total card shows violet |
| AW8-2 | Manually set all tenant balances < 0 in DB | Total card shows red |

## LMS-UX-005 — Filter chip counts in AdminCertificates

### Current Behaviour
Both `ApplicationsPanel` and `IssuedPanel` fetch filtered results from the API when a
non-"All" filter is active (e.g. `getAllCertificates({ status: 'pending' })`). Because the
returned array only contains matching records, derived counts for other statuses are always 0,
and the "All" chip shows the filtered count rather than the true total. Visible counts:

- Filter = "All": `All (42) · Pending (8) · Approved (3) · Minted (27) · Rejected (4)` ✓
- Filter = "Pending": `All (8) · Pending (8) · Approved (0) · Minted (0) · Rejected (0)` ✗

### Desired Behaviour
- When `statusFilter === 'all'` (or `mintStatusFilter === 'all'`): counts visible on all chips.
- When any specific filter is active: count badges hidden on all chips.

### Implementation (applied 2026-07-26)

**AdminCertificates.tsx:264** (`ApplicationsPanel`) — before:
```tsx
{label}
<span className="tabular-nums font-bold">{count}</span>
```
After:
```tsx
{label}
{statusFilter === 'all' && <span className="tabular-nums font-bold">{count}</span>}
```

**AdminCertificates.tsx:545** (`IssuedPanel`) — before:
```tsx
{label}
<span className="tabular-nums font-bold">{count}</span>
```
After:
```tsx
{label}
{mintStatusFilter === 'all' && <span className="tabular-nums font-bold">{count}</span>}
```

The "Superseded" static badge (line 551) is left unchanged — it is not a filter chip and
always reflects the true count of superseded rows in the current result set.

### Constraints
- Frontend only — no backend change, no new dependencies.
- Fix applies to both `ApplicationsPanel` and `IssuedPanel`.

### Test Strategy
| ID | Steps | Pass criterion |
|----|-------|----------------|
| UX5-1 | Open Certificates page, Tab = Applications, Filter = All | All chips show numeric counts |
| UX5-2 | Click "Pending" chip | Count badges disappear from all chips |
| UX5-3 | Click "All" chip | Counts reappear |
| UX5-4 | Switch to Issued NFTs tab, Filter = All | All chips show counts |
| UX5-5 | Click "Minted" chip | Counts disappear |
